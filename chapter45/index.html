    Chapter 45: 발표와 성찰 - 우리의 여정을 돌아보며¶

    🎯 이 장의 학습 목표¶

    이 장을 마치면 다음을 할 수 있습니다:

    • [ ] 프로젝트 과정과 결과를 '문제-해결책-시연-배운점' 구조로 발표할 수 있다
    • [ ] 팀 활동과 개인 성장을 성찰하고 포트폴리오로 기록할 수 있다
    • [ ] 45차시의 학습 여정을 돌아보고, 앞으로의 방향을 설계할 수 있다

    예상 학습 시간: 약 50분

    📚 미리 알아야 할 것¶

    지금까지 여러분은 정말 긴 여정을 걸어왔어요. 1권에서 파이썬의 기초를 배우고, 2권에서는 실제 사회문제를 해결하는 프로젝트를 만들었습니다. 이제 마지막 챕터입니다! 🎉

    이 장은 코딩 실력보다 "돌아보고 정리하는 힘"에 집중합니다. 프로젝트를 발표하고, 자신의 성장을 기록하는 것이야말로 진짜 개발자로 가는 길이에요.

    💡 왜 이걸 배우나요?¶

    코드를 잘 짜는 것만큼 중요한 게 있어요. 바로 "내가 만든 것을 다른 사람에게 설명하는 능력"입니다.

    세상에서 가장 뛰어난 프로그램도 아무도 모르면 의미가 없어요. 개발자들이 GitHub에 README를 쓰고, 회사에서 데모 발표를 하는 이유가 바로 이것이에요.

    그리고 한 가지 더 — 성찰(돌아보기)은 단순한 회고가 아닙니다. "나는 어디서 막혔고, 어떻게 해결했는지"를 기록하는 것은 다음 프로젝트의 설계도가 됩니다.

    💡 이 장은 특별해요! 45차시의 마지막 장입니다. 코드보다는 여러분 자신에 집중하는 시간이에요. 편안한 마음으로 읽어주세요.

    📚 핵심 개념¶

    개념 1: 프로젝트 발표 구조 🎤¶

    발표를 처음 해보는 사람도 걱정하지 마세요. 정해진 틀만 따라가면 누구나 깔끔한 발표를 할 수 있어요. 이것을 "PSDL 구조"라고 부를게요.

    PSDL이 뭐냐고요? 발표를 네 단계로 나눈 거예요:

    • P (Problem) — 어떤 문제를 발견했나요?
    • S (Solution) — 어떻게 해결했나요?
    • D (Demo) — 실제로 작동하는 모습을 보여주세요
    • L (Lesson) — 무엇을 배웠나요?

    이건 마치 영화의 기승전결과 같아요. 문제라는 갈등이 있고, 해결책이라는 전개가 있고, 시연이라는 클라이맥스가 있고, 배운 점이라는 결말이 있죠.

    # 발표 구조를 코드로 표현하면 이런 느낌이에요
presentation = {
    "1_problem": "우리 동네 쓰레기 무단투기가 심각해요",
    "2_solution": "CCTV 데이터를 분석해서 다발 지역을 지도에 표시했어요",
    "3_demo": "프로그램을 실행해서 실제 결과를 보여드릴게요",
    "4_lesson": "데이터 정제가 전체 시간의 70%를 차지한다는 걸 배웠어요"
}

for step, content in presentation.items():
    print(f"📌 {step}: {content}")

    실행 결과: 

    📌 1_problem: 우리 동네 쓰레기 무단투기가 심각해요
📌 2_solution: CCTV 데이터를 분석해서 다발 지역을 지도에 표시했어요
📌 3_demo: 프로그램을 실행해서 실제 결과를 보여드릴게요
📌 4_lesson: 데이터 정제가 전체 시간의 70%를 차지한다는 걸 배웠어요

    개념 2: 피드백 주고받기 🔄¶

    발표가 끝나면 서로 피드백을 나눠요. 좋은 피드백에는 공식이 있습니다.

    "샌드위치 피드백" — 칭찬 사이에 개선점을 넣는 거예요.

    def give_feedback(good_point, improvement, encouragement):
    """좋은 피드백을 만드는 함수"""
    print(f"👍 좋았던 점: {good_point}")
    print(f"💡 이러면 더 좋겠어요: {improvement}")
    print(f"🌟 응원 한마디: {encouragement}")

# 예시
give_feedback(
    "데이터 시각화가 정말 직관적이었어요",
    "사용자 입력 처리에서 예외 처리를 추가하면 더 안정적일 것 같아요",
    "이 프로젝트 완성도가 높아서 실제로 사용할 수 있을 것 같아요!"
)

    실행 결과: 

    👍 좋았던 점: 데이터 시각화가 정말 직관적이었어요
💡 이러면 더 좋겠어요: 사용자 입력 처리에서 예외 처리를 추가하면 더 안정적일 것 같아요
🌟 응원 한마디: 이 프로젝트 완성도가 높아서 실제로 사용할 수 있을 것 같아요!

    💡 기억하세요! 피드백은 "틀렸다"가 아니라 "이렇게 하면 더 좋겠다"예요. 서로를 성장시키는 대화입니다.

    개념 3: 성찰 기록 (회고록) 📓¶

    성찰은 "나를 돌아보는 것"이에요. 개발자 세계에서는 이것을 회고(Retrospective)라고 불러요. 스프린트가 끝날 때마다 팀이 모여서 하는 중요한 활동이죠.

    회고에는 유명한 프레임워크가 있어요. KPT 방식입니다:

    • K (Keep) — 계속 유지할 것 (잘한 것)
    • P (Problem) — 문제였던 것
    • T (Try) — 다음에 시도할 것
    def write_retrospective():
    """나만의 회고록 작성기"""
    print("=" * 40)
    print("📓 나의 프로젝트 회고록")
    print("=" * 40)

    # Keep - 잘한 것
    keeps = []
    print("\n✅ [Keep] 잘한 것, 계속하고 싶은 것:")
    while True:
        item = input("  → (입력 후 Enter, 끝내려면 빈칸): ")
        if item == "":
            break
        keeps.append(item)

    # Problem - 어려웠던 것
    problems = []
    print("\n⚠️ [Problem] 어려웠거나 아쉬웠던 것:")
    while True:
        item = input("  → (입력 후 Enter, 끝내려면 빈칸): ")
        if item == "":
            break
        problems.append(item)

    # Try - 다음에 시도할 것
    tries = []
    print("\n🚀 [Try] 다음에 시도해보고 싶은 것:")
    while True:
        item = input("  → (입력 후 Enter, 끝내려면 빈칸): ")
        if item == "":
            break
        tries.append(item)

    # 결과 출력
    print("\n" + "=" * 40)
    print("📋 나의 회고 요약")
    print("=" * 40)
    for k in keeps:
        print(f"  ✅ {k}")
    for p in problems:
        print(f"  ⚠️ {p}")
    for t in tries:
        print(f"  🚀 {t}")

    return {"keep": keeps, "problem": problems, "try": tries}

    개념 4: 포트폴리오 정리와 다음 단계 🗂️¶

    포트폴리오란 "나의 작품 모음집"이에요. 화가가 그림을 모아두는 것처럼, 개발자도 자신이 만든 프로젝트를 정리해둡니다.

    def create_portfolio_entry(project_name, description, skills, github_url=""):
    """포트폴리오 항목 생성"""
    entry = f"""
{'='*50}
📁 프로젝트: {project_name}
{'='*50}
📝 설명: {description}
🛠️ 사용 기술: {', '.join(skills)}
🔗 저장소: {github_url if github_url else '아직 없음'}
📅 기간: 2025년 학습 기간 중
{'='*50}
"""
    return entry

# 예시: 여러분의 사회문제 해결 프로젝트
my_project = create_portfolio_entry(

    ["Python", "pandas", "matplotlib", "공공데이터 API"]
)
print(my_project)

    🔨 따라하기: 나의 학습 여정 정리하기¶

    Step 1: 발표 스크립트 작성하기¶

    # 발표 스크립트를 구조화해봅시다
def create_presentation_script():
    script = {}

    print("🎤 발표 스크립트를 만들어봅시다!\n")

    # 1단계: 문제 정의
    script["problem"] = input("1️⃣ 어떤 사회 문제를 선택했나요?\n→ ")
    script["why"] = input("   왜 이 문제가 중요한가요?\n→ ")

    # 2단계: 해결 방법
    script["solution"] = input("\n2️⃣ 어떻게 해결했나요? (프로그램 설명)\n→ ")
    script["tech"] = input("   어떤 기술을 사용했나요?\n→ ")

    # 3단계: 시연 메모
    script["demo_note"] = input("\n3️⃣ 시연할 때 보여줄 핵심 기능은?\n→ ")

    # 4단계: 배운 점
    script["lesson"] = input("\n4️⃣ 이 프로젝트에서 가장 크게 배운 점은?\n→ ")

    return script

    ✅ 체크포인트: 네 가지 항목(문제-해결-시연-교훈)이 모두 채워졌나요?

    Step 2: 발표 시간 계산기¶

    발표 시간은 보통 5~10분이에요. 너무 길면 집중력이 떨어지고, 너무 짧으면 내용을 전달하기 어렵죠.

    def estimate_presentation_time(script_text):
    """발표 시간 예측기 (1분에 약 300자 기준)"""
    char_count = len(script_text)
    minutes = char_count / 300

    print(f"📊 스크립트 글자 수: {char_count}자")
    print(f"⏱️ 예상 발표 시간: 약 {minutes:.1f}분")

    if minutes < 3:
        print("💡 조금 더 내용을 추가해보세요!")
    elif minutes > 10:

    print("📔 나의 성장 일지\n")

    questions = [
        ("🌱 학습 전의 나", "프로그래밍을 시작하기 전, 코딩에 대한 나의 생각은?"),
        ("🌿 학습 중 가장 힘들었던 순간", "어떤 부분이 가장 어려웠고, 어떻게 극복했나요?"),
        ("🌳 지금의 나", "45차시를 마친 지금, 달라진 점은?"),
        ("🌟 가장 뿌듯한 순간", "학습 과정에서 가장 기뻤던 순간은?"),
    ]

    journal = {}
    for emoji_title, question in questions:
        print(f"{emoji_title}")
        print(f"  Q: {question}")
        answer = input("  A: ")
        journal[emoji_title] = answer
        print()

    # 저장
    with open("my_growth_journal.txt", "w", encoding="utf-8") as f:
        f.write("📔 나의 성장 일지\n")
        f.write("=" * 40 + "\n\n")
        for title, answer in journal.items():
            f.write(f"{title}\n{answer}\n\n")

    print("💾 'my_growth_journal.txt'에 저장되었습니다!")
