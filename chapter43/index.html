    Chapter 43: 프로토타입 개발하기¶

    🎯 이 장의 학습 목표¶

    이 장을 마치면 다음을 할 수 있습니다:

    • [ ] 설계에 따라 하드웨어를 조립하고 연결할 수 있다
    • [ ] 핵심 기능을 구현하는 코드를 작성할 수 있다
    • [ ] 팀원과 협력하여 문제를 해결하고 진행상황을 공유할 수 있다
    • [ ] 시행착오를 기록하고 개선 방향을 도출할 수 있다

    예상 학습 시간: 약 90분

    📚 미리 알아야 할 것¶

    이전 장(Chapter 42)에서 우리는 사회문제 해결을 위한 시스템 설계를 완료했어요. 어떤 센서를 쓸지, 회로를 어떻게 연결할지, 코드의 흐름은 어떻게 될지를 설계도로 정리했죠.

    이번 장에서는 드디어 그 설계도를 실제로 만들어보는 시간입니다! 🎉

    💡 왜 이걸 배우나요?¶

    아무리 완벽한 설계도를 그려도, 실제로 만들어보면 예상과 다른 일이 반드시 일어납니다.

    요리 레시피를 아무리 꼼꼼히 읽어도 직접 만들어봐야 "아, 불 조절이 이래서 타는구나"를 알게 되는 것과 같아요. 프로토타입 개발은 바로 그 "직접 만들어보는" 과정입니다.

    🍳 비유하자면: 설계는 레시피를 쓰는 것, 프로토타입은 실제로 요리하는 것! 맛이 좀 이상해도 괜찮아요. 첫 시도부터 완벽한 요리사는 없으니까요.

    프로토타입(Prototype)이란 "최종 완성품이 아닌, 핵심 기능을 시험해보는 시제품"을 말해요. 완벽하지 않아도 됩니다. 중요한 건 "되는지 안 되는지 확인하는 것"이에요.

    📚 핵심 개념¶

    개념 1: 프로토타입 개발의 3단계¶

    프로토타입 개발은 마치 집을 짓는 과정과 비슷해요.

    • 1단계 - 하드웨어 조립 = 집의 뼈대를 세우는 것 🏗️
    • 2단계 - 기본 코드 작성 = 전기와 수도를 연결하는 것 ⚡
    • 3단계 - 테스트와 수정 = 직접 살아보며 고치는 것 🔧

    세 단계를 한꺼번에 하려 하지 말고, 하나씩 차근차근 진행하는 것이 핵심이에요.

    flowchart LR A["🏗️ 하드웨어 조립"] --> B["💻 기본 코드 작성"] --> C["🔧 테스트 & 수정"] C -->|문제 발견| A C -->|코드 수정| B style A fill:#e3f2fd,stroke:#1976d2 style B fill:#fff3e0,stroke:#f57c00 style C fill:#e8f5e9,stroke:#388e3c

    💡 핵심 포인트: 테스트에서 문제가 발견되면 다시 앞 단계로 돌아가는 건 아주 자연스러운 일이에요!

    개념 2: MVP(최소 기능 제품) 마인드셋¶

    MVP는 Minimum Viable Product, 즉 "핵심 기능만 작동하는 최소한의 제품"이에요.

    처음부터 모든 기능을 다 넣으려 하면 하나도 완성하지 못할 수 있어요. 대신 가장 중요한 기능 1~2개만 먼저 완성하세요.

    예를 들어 "독거노인 안전 확인 시스템"을 만든다면:

    • MVP: 초음파 센서로 움직임을 감지해서 LED를 켜는 것 ✅
    • 나중에 추가: 일정 시간 움직임이 없으면 알림 보내기
    • 더 나중에: 데이터를 저장하고 패턴 분석하기

    🎯 기억하세요: "완벽한 미완성"보다 "불완전한 완성"이 100배 낫습니다!

    개념 3: 디버깅 = 탐정 놀이 🔍¶

    코드나 회로가 제대로 작동하지 않을 때, 원인을 찾아 고치는 과정을 디버깅(Debugging)이라고 해요.

    디버깅은 마치 탐정이 단서를 추적하는 것과 같아요:

    • 🔍 증상 확인: "어떤 현상이 발생하는가?" (LED가 안 켜진다, 값이 이상하다 등)
    • 🤔 용의자 좁히기: "어디가 문제일까?" (회로? 코드? 센서?)
    • 🧪 하나씩 테스트: 한 번에 하나만 바꿔보며 확인
    • 📝 기록하기: 무엇을 바꿨고, 결과가 어땠는지 메모

    개념 4: 개발 일지 작성법¶

    프로토타입을 만들면서 겪은 과정을 기록하는 것은 매우 중요해요. 이것을 개발 일지라고 합니다.

    개발 일지에는 이런 내용을 적어요:

    • 📅 날짜와 시간
    • 🎯 오늘 할 일: 무엇을 구현할 계획인지
    • ✅ 완료한 것: 실제로 완성한 것
    • ❌ 막힌 것: 문제가 된 부분과 원인
    • 💡 배운 것: 시행착오에서 알게 된 점
    • 📋 다음에 할 일: 이어서 작업할 내용

    💡 잠깐! 여기까지 이해가 잘 되셨나요? 네 가지 핵심 개념을 정리하면: 단계별 개발 → MVP 마인드 → 디버깅 → 기록이에요. 이 네 가지만 기억하면 프로토타입 개발의 80%는 준비된 거예요!

    🔨 따라하기¶

    이제 실제로 프로토타입을 개발해볼까요? 여기서는 "교실 소음 측정기"를 예시로 진행합니다. 여러분은 자신의 프로젝트에 맞게 응용하세요!

    Step 1: 하드웨어 조립하기 🏗️¶

    목표: 설계도를 보고 부품을 브레드보드에 연결합니다.

    먼저 설계도에 적힌 부품 목록을 꺼내고, 실물과 대조하세요.

    [체크리스트]
□ 마이크로비트 (또는 아두이노)
□ 소리 센서 모듈
□ LED (또는 네오픽셀)
□ 점퍼 와이어 3~4개
□ USB 케이블

    연결 방법 (소리 센서 기준): - 소리 센서 VCC → 마이크로비트 3V - 소리 센서 GND → 마이크로비트 GND - 소리 센서 OUT → 마이크로비트 Pin 0

    ✅ 체크포인트: 연결 후 USB를 꽂아서 마이크로비트에 불이 들어오면 성공이에요!

    Step 2: 센서 값 읽기 (기본 코드) 💻¶

    하드웨어가 연결되었으면, 센서가 제대로 작동하는지 확인하는 코드를 먼저 작성해요.

    # 교실 소음 측정기 - Step 2: 센서 값 읽기
from microbit import *

while True:
    sound_level = pin0.read_analog()  # 소리 센서 값 읽기
    print(sound_level)                # 시리얼 모니터에 출력
    sleep(500)                        # 0.5초마다 반복

    이 코드를 업로드하고, 시리얼 모니터를 열어보세요. 숫자가 계속 변하면서 나타나면 센서가 잘 작동하는 거예요!

    • 조용할 때: 대략 100~200 정도
    • 시끄러울 때: 500 이상

    ✅ 체크포인트: 시리얼 모니터에 숫자가 보이면 성공! 손뼉을 쳐보면 숫자가 확 올라가야 해요.

    Step 3: 핵심 기능 구현하기 🎯¶

    센서가 작동하는 걸 확인했으니, 이제 핵심 기능을 추가합니다. 소음 수준에 따라 LED 표시를 바꿔볼게요.

    # 교실 소음 측정기 - Step 3: 핵심 기능
from microbit import *

# 소음 기준값 설정
QUIET = 200      # 조용함 기준
NORMAL = 400     # 보통 기준
LOUD = 600       # 시끄러움 기준

while True:
    sound_level = pin0.read_analog()

    if sound_level < QUIET:
        display.show(Image.HAPPY)       # 😊 조용해요
    elif sound_level < NORMAL:
        display.show(Image.MEH)         # 😐 보통이에요
    elif sound_level < LOUD:
        display.show(Image.SAD)         # 😟 좀 시끄러워요
    else:
        display.show(Image.ANGRY)       # 😠 너무 시끄러워요!

    sleep(300)

    💡 팁: 기준값(QUIET, NORMAL, LOUD)은 여러분의 환경에 맞게 조정하세요! Step 2에서 확인한 숫자를 참고하면 돼요.

    Step 4: 테스트하고 문제 해결하기 🔧¶

    코드를 올렸는데 예상대로 작동하지 않나요? 당연한 거예요! 이제 디버깅 시간입니다.

    자주 발생하는 문제와 해결법:

    문제 1: 센서 값이 항상 0이에요 - 점퍼 와이어 연결을 다시 확인하세요 - VCC와 GND가 바뀌지 않았는지 체크!

    문제 2: 표정이 계속 ANGRY만 나와요 - 기준값이 너무 낮은 거예요 - Step 2의 코드로 돌아가서 실제 값을 다시 확인한 후 기준값을 조정하세요

    문제 3: 표정이 너무 빨리 바뀌어요 - sleep(300)을 sleep(1000)으로 바꿔보세요

    # 디버깅용 코드: 센서값과 판단 결과를 동시에 확인
from microbit import *

QUIET = 200
NORMAL = 400
LOUD = 600

while True:
    sound_level = pin0.read_analog()

    # 디버깅: 현재 값 출력
    if sound_level < QUIET:
        status = "QUIET"
    elif sound_level < NORMAL:
        status = "NORMAL"
    elif sound_level < LOUD:
        status = "LOUD"
    else:
        status = "TOO LOUD"

    print("Level:", sound_level, "->", status)  # ← 이 줄이 핵심!
    sleep(500)

    ✅ 체크포인트: print() 문으로 현재 상태를 확인하는 습관을 들이세요. 이것이 디버깅의 가장 기본이에요!

    Step 5: 추가 기능 확장하기 ✨¶

    MVP가 작동하면, 한 가지씩 기능을 추가해보세요.

    # 교실 소음 측정기 - Step 5: 경고음 추가
from microbit import *
import music

QUIET = 200
NORMAL = 400
LOUD = 600

loud_count = 0  # 시끄러운 횟수 카운트

while True:
    sound_level = pin0.read_analog()

    if sound_level < QUIET:
        display.show(Image.HAPPY)
        loud_count = 0  # 조용하면 카운트 초기화
    elif sound_level < NORMAL:
        display.show(Image.MEH)
    elif sound_level < LOUD:
        display.show(Image.SAD)
        loud_count += 1
    else:
        display.show(Image.ANGRY)
        loud_count += 1

    # 3번 연속 시끄러우면 경고음!
    if loud_count >= 3:
        music.play("C5:2")  # 짧은 경고음
        loud_count = 0

    sleep(500)

    💡 자기 프로젝트에 적용하기: 위 예제는 소음 측정기이지만, 여러분 프로젝트도 같은 패턴이에요. 센서 읽기 → 판단하기 → 반응하기 → 추가 기능의 흐름을 따라가 보세요!

    📝 전체 코드¶

    최종 완성된 교실 소음 측정기의 전체 코드입니다:

    # 🔊 교실 소음 측정기 v1.0
# 사회문제: 교실 소음으로 인한 학습 방해 해결
from microbit import *
import music

# === 설정값 (환경에 맞게 조정하세요) ===
QUIET = 200
NORMAL = 400
LOUD = 600

# === 변수 초기화 ===
loud_count = 0

# === 메인 루프 ===
while True:
    # 1. 센서 값 읽기
    sound_level = pin0.read_analog()

    # 2. 소음 수준 판단 & 표시
    if sound_level < QUIET:
        display.show(Image.HAPPY)
        loud_count = 0
    elif sound_level < NORMAL:
        display.show(Image.MEH)
    elif sound_level < LOUD:
        display.show(Image.SAD)
        loud_count += 1
    else:
        display.show(Image.ANGRY)
        loud_count += 1

    # 3. 연속 소음 경고
    if loud_count >= 3:
        music.play("C5:2")
        loud_count = 0

    # 4. 디버깅용 출력 (완성 후 삭제 가능)
    print("Sound:", sound_level, "Count:", loud_count)

    sleep(500)

    ⚠️ 자주 하는 실수¶

    실수 1: 모든 기능을 한꺼번에 구현하려 한다 😵 - 왜 이런 일이 생기나요? 빨리 완성하고 싶은 마음이 앞서기 때문이에요. - 이렇게 해결해요: 센서 읽기 → 기본 반응 → 추가 기능 순서로 하나씩 추가하세요. 각 단계에서 작동을 확인한 뒤 다음으로 넘어가세요.

    실수 2: 하드웨어 문제를 코드 문제로 착각한다 🔌 - 왜 이런 일이 생기나요? 코드만 계속 수정하다 보면 점퍼 와이어가 빠져 있는 걸 놓치기 쉬워요. - 이렇게 해결해요: 코드를 수정하기 전에 항상 연결 상태를 먼저 확인하세요. 선이 느슨하지 않은지, 핀 번호가 맞는지 체크!

    실수 3: 시행착오를 기록하지 않는다 📝 - 왜 이런 일이 생기나요? "나중에 기억하겠지"라고 생각하지만, 절대 기억 못 합니다! - 이렇게 해결해요: 문제가 발생할 때마다 즉시 메모하세요. "OO 핀을 XX로 바꿨더니 해결됨" 한 줄이면 충분해요.

    실수 4: print() 디버깅을 하지 않는다 🖨️ - 왜 이런 일이 생기나요? 코드만 눈으로 읽으면서 "맞는데 왜 안 되지?" 고민하는 경우가 많아요. - 이렇게 해결해요: 의심되는 곳마다 print()를 넣어서 실제로 어떤 값이 들어있는지 확인하세요. 이것만으로도 대부분의 버그를 찾을 수 있어요!
