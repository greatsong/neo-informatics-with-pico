    프로토타입 설계하기¶

    🎯 이 장의 학습 목표¶

    • [ ] 하드웨어 구성도와 소프트웨어 흐름도를 설계할 수 있다
    • [ ] 팀원 역할 분담과 개발 일정을 계획할 수 있다

    예상 학습 시간: 약 40분

    📚 미리 알아야 할 것¶

    이전 장에서 사회문제를 분석하고 아이디어를 선정했죠? 이제 그 아이디어를 실제로 만들기 위한 설계도를 그릴 차례예요. 건물을 짓기 전에 건축 도면을 그리듯, 프로토타입(시제품)을 만들기 전에 설계를 먼저 해야 합니다.

    📚 핵심 개념¶

    개념 1: 하드웨어 구성도¶

    비유로 시작: 하드웨어 구성도는 마치 요리 재료 배치도와 같아요. 어떤 재료(센서, 모터 등)를 어디에 놓고, 서로 어떻게 연결할지 한눈에 보여주는 그림이에요.

    정확한 정의: 프로젝트에 사용할 센서, 출력장치, 마이크로컨트롤러(아두이노 등) 간의 연결 관계를 시각적으로 표현한 도면입니다.

    예시로 확인: "독거노인 안전 알림 시스템"을 만든다고 해볼게요.

    flowchart LR A["🌡️ 온도센서\n(A0 핀)"] --> D["🧠 아두이노\n(중앙 처리)"] B["🚶 움직임센서\n(D2 핀)"] --> D C["🔘 긴급버튼\n(D3 핀)"] --> D D --> E["🔴 LED 경고등\n(D8 핀)"] D --> F["🔊 부저\n(D9 핀)"] D --> G["📡 블루투스\n(D10,D11 핀)"]

    이렇게 그려두면 어떤 부품이 필요한지, 어떤 핀에 연결할지 한눈에 파악할 수 있어요.

    💡 잠깐! 구성도를 그릴 때는 각 부품 옆에 연결할 핀 번호를 꼭 적어두세요. 나중에 실제 조립할 때 헷갈리지 않아요!

    개념 2: 소프트웨어 흐름도¶

    비유로 시작: 소프트웨어 흐름도는 마치 보드게임 말판과 같아요. "시작"에서 출발해서, 갈림길(조건)을 만나면 방향을 선택하고, 특정 칸(동작)을 수행하며 진행하는 거예요.

    정확한 정의: 프로그램이 실행되는 순서를 도형과 화살표로 표현한 것입니다. 조건 판단은 마름모, 동작은 직사각형으로 그려요.

    예시로 확인: 같은 "독거노인 안전 알림 시스템"의 흐름도예요.

    flowchart TD A(["▶ 시작"]) --> B["센서값 읽기"] B --> C{"움직임이\n감지되었나?"} C -->|Yes| D["정상 상태 기록"] C -->|No| E{"30분 이상\n움직임 없음?"} E -->|No| B E -->|Yes| F["⚠️ LED 켜기 + 부저 울리기"] F --> G["📡 보호자에게 알림 전송"] G --> B D --> B

    💡 팁! 흐름도를 먼저 그리면 코딩할 때 "다음에 뭘 해야 하지?" 하고 막히는 일이 줄어들어요. 설계가 곧 코딩의 지도예요! 🗺️

    🔨 따라하기: 나만의 프로토타입 설계서 작성¶

    여러분의 프로젝트에 맞게 설계서를 작성해봅시다. 아래 단계를 따라가며 종이나 노트에 직접 적어보세요!

    Step 1: 부품 목록 정리하기¶

    먼저 프로젝트에 필요한 부품을 정리해요. 아래 형식을 참고하세요.

    코드 (주석으로 설계 내용을 정리하는 방법): 

    # =============================
# 프로젝트: 독거노인 안전 알림 시스템
# =============================

# [부품 목록]
# - 입력장치: 온도센서(LM35), PIR 움직임센서, 푸시버튼
# - 출력장치: LED(빨강), 피에조 부저
# - 통신장치: HC-06 블루투스 모듈
# - 제어장치: 아두이노 우노

# [핀 연결 계획]
INPUT_TEMP = "A0"       # 온도센서 → 아날로그 0번
INPUT_PIR = 2           # 움직임센서 → 디지털 2번
INPUT_BUTTON = 3        # 긴급버튼 → 디지털 3번
OUTPUT_LED = 8          # LED → 디지털 8번
OUTPUT_BUZZER = 9       # 부저 → 디지털 9번

    ✅ 체크포인트: 여러분의 프로젝트 부품과 핀 번호를 적어보셨나요?

    Step 2: 주요 기능 나열하기¶

    프로그램이 해야 할 일을 목록으로 적어요.

    # [주요 기능]
# 기능1: 센서로 움직임 감지 → 30분 이상 없으면 경고
# 기능2: 온도가 35도 이상이면 고온 경고
# 기능3: 긴급버튼 누르면 즉시 알림 전송
# 기능4: 블루투스로 보호자 앱에 상태 전송

    Step 3: 흐름도 그리기¶

    Step 2의 기능을 바탕으로 순서도를 그려요. 종이에 손으로 그려도 좋고, 아래처럼 코드 주석으로 정리해도 돼요.

    # [프로그램 흐름]
# 1. 시작 → 센서 초기화
# 2. 반복 시작 ────────────────┐
#    3. 움직임 센서 읽기        │
#    4. 움직임 있음? → 시간 초기화│
#    5. 움직임 없음?            │
#       → 30분 경과? → 경고!   │
#    6. 긴급버튼 눌림? → 알림!  │
#    7. 온도 읽기 → 35도↑? → 경고│
#    8. 1초 대기               │
# 9. 반복 끝 ──────────────────┘

    Step 4: 역할 분담하기¶

    팀 프로젝트라면 역할을 나눠야 해요. 혼자 하더라도 작업 영역을 구분해두면 효율적이에요.

    # [역할 분담]
# 하드웨어 담당: 회로 연결, 센서 테스트 → (이름)
# 소프트웨어 담당: 코딩, 디버깅 → (이름)
# 디자인 담당: 외관, 케이스 제작 → (이름)  
# 문서화 담당: 보고서, 발표자료 → (이름)

    Step 5: 3차시 개발 일정 세우기¶

    # [개발 일정]
# 1차시: 하드웨어 조립 + 개별 센서 테스트
#        → 목표: 각 센서가 값을 제대로 읽는지 확인
#
# 2차시: 소프트웨어 통합 + 기능 연결
#        → 목표: 전체 흐름도대로 프로그램 동작 확인
#
# 3차시: 테스트 + 수정 + 외관 정리
#        → 목표: 시연 가능한 완성품 만들기

    ✅ 체크포인트: 각 차시마다 구체적인 목표가 적혀 있나요? "열심히 한다" 같은 추상적 목표는 피해주세요! 😄

    ⚠️ 주의할 점¶

    1. 설계 없이 바로 만들기 시작하지 마세요! "일단 조립부터 하자"라고 하면 중간에 핀이 부족하거나 센서끼리 충돌하는 문제가 생겨요. 설계서를 먼저 작성하면 이런 문제를 미리 예방할 수 있어요.

    2. 너무 많은 기능을 넣지 마세요! 프로토타입은 핵심 기능 3~4개만 구현하는 게 좋아요. "이것도 넣고 저것도 넣자"라고 하면 하나도 제대로 완성하지 못할 수 있어요. 기본이 되면 나중에 추가하면 됩니다.

    ✅ 점검하기¶

    1. 하드웨어 구성도에 반드시 포함해야 할 3가지는?

    정답 확인 사용할 **부품 이름**, 부품 간의 **연결 관계(화살표)**, 각 부품의 **핀 번호**가 포함되어야 해요.

    2. 흐름도에서 마름모 모양은 무엇을 의미하나요?

    정답 확인 **조건 판단(분기)**을 의미해요. "움직임이 있는가?", "온도가 35도 이상인가?" 같은 Yes/No 질문이 들어가요.

    3. 프로토타입 설계에서 기능을 3~4개로 제한하는 이유는?

    정답 확인 너무 많은 기능을 한꺼번에 구현하려면 시간 내에 완성하기 어렵고, 핵심 기능조차 제대로 동작하지 않을 수 있기 때문이에요. **핵심부터 완성하고 나중에 확장**하는 것이 좋아요!
