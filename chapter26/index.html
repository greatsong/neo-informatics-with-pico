    예외 처리 - 오류에도 멈추지 않는 프로그램¶

    🎯 이 장의 학습 목표¶

    이 장을 마치면 다음을 할 수 있습니다:

    • [ ] try-except 구문으로 예외를 처리할 수 있다
    • [ ] 오류가 발생해도 멈추지 않는 견고한 프로그램을 작성할 수 있다

    예상 학습 시간: 약 40분

    📚 미리 알아야 할 것¶

    • 함수를 만들고 호출하는 방법 (이전 장에서 학습)
    • if-else 조건문의 기본 사용법

    📚 핵심 개념¶

    개념 1: 예외(Exception)란?¶

    프로그램을 실행하다 보면 예상치 못한 오류가 발생할 수 있어요. 이걸 예외(Exception)라고 합니다.

    먼저 오류가 어떻게 생기는지 직접 봐볼까요?

    # 숫자를 0으로 나누면?
result = 10 / 0
print(result)

    ZeroDivisionError: division by zero

    프로그램이 즉시 멈춰버립니다. 이 아래에 아무리 중요한 코드가 있어도 실행되지 않아요.

    🤔 생각해보세요: 센서가 100개 달린 스마트팜에서 센서 1개가 고장났다고 전체 프로그램이 멈춘다면? 농작물 전체가 위험해질 수 있어요!

    개념 2: try-except — 프로그램의 안전망¶

    try-except는 마치 안전망과 같아요.

    서커스 공중그네를 생각해보세요. 곡예사가 실수로 떨어져도 아래에 안전망이 있으면 다치지 않죠? try-except가 바로 그 안전망이에요.

    flowchart TD A["try 블록<br/>위험할 수 있는 코드 실행"] -->|성공| B["정상 진행 ✅"] A -->|오류 발생!| C["except 블록<br/>안전망이 받아줌 🛡️"] C --> D["프로그램 계속 실행"] B --> D style A fill:#fff3e0,stroke:#f57c00 style B fill:#e8f5e9,stroke:#388e3c style C fill:#e3f2fd,stroke:#1976d2 style D fill:#e8f5e9,stroke:#388e3c

    정확한 정의: try 블록 안의 코드를 실행하다 오류가 나면, 프로그램을 멈추지 않고 except 블록의 코드를 대신 실행합니다.

    try:
    result = 10 / 0          # 오류 발생!
    print(result)             # 이 줄은 실행 안 됨
except:
    print("오류가 발생했습니다!")  # 안전망이 작동!

print("프로그램은 계속됩니다 😊")

    오류가 발생했습니다!
프로그램은 계속됩니다 😊

    프로그램이 멈추지 않았어요! 이것이 try-except의 힘입니다.

    💡 잠깐! 여기까지 이해가 잘 되셨나요? try = "시도해봐", except = "실패하면 이렇게 해"로 기억하면 쉬워요!

    🔨 따라하기: 센서 오류에 대응하는 프로그램¶

    스마트팜의 온도 센서가 가끔 고장나는 상황을 시뮬레이션해봅시다. 센서가 오류를 일으켜도 프로그램이 멈추지 않도록 만들어볼게요.

    Step 1: 오류가 나는 센서 만들기¶

    센서가 가끔 고장나는 상황을 함수로 만들어요.

    import random

def read_temperature_sensor():
    """가끔 오류가 나는 온도 센서"""
    if random.random() < 0.3:  # 30% 확률로 고장
        raise ValueError("센서 응답 없음!")
    return round(random.uniform(20.0, 30.0), 1)

    📝 raise는 일부러 오류를 발생시키는 명령어예요. 실제 센서 고장을 흉내 내는 거죠.

    Step 2: try-except로 안전하게 센서 읽기¶

    try:
    temp = read_temperature_sensor()
    print(f"현재 온도: {temp}°C")
except ValueError as e:
    print(f"⚠️ 센서 오류: {e}")

    ValueError as e라고 쓰면 오류 메시지를 e에 저장해서 어떤 오류인지 확인할 수 있어요.

    Step 3: 마지막 정상값을 기억하기¶

    센서가 고장나면 마지막으로 정상이었던 값을 사용하는 방법이 실무에서 많이 쓰여요.

    last_good_temp = 25.0  # 초기 기본값

for i in range(5):
    try:
        temp = read_temperature_sensor()
        last_good_temp = temp  # 정상값 저장!
        print(f"[{i+1}] ✅ 온도: {temp}°C")
    except ValueError:
        print(f"[{i+1}] ⚠️ 오류! 마지막 정상값 사용: {last_good_temp}°C")

    실행 결과 (매번 다를 수 있어요): 

    [1] ✅ 온도: 24.3°C
[2] ⚠️ 오류! 마지막 정상값 사용: 24.3°C
[3] ✅ 온도: 27.1°C
[4] ✅ 온도: 22.8°C
[5] ⚠️ 오류! 마지막 정상값 사용: 22.8°C

    ✅ 체크포인트: 오류가 발생한 줄에서도 프로그램이 멈추지 않고 계속 돌아가나요? 그렇다면 성공이에요!

    Step 4: 오류 횟수 세기¶

    몇 번이나 오류가 났는지 기록해두면 센서 교체 시기를 판단할 수 있어요.

    last_good_temp = 25.0
error_count = 0

for i in range(10):
    try:
        temp = read_temperature_sensor()
        last_good_temp = temp
    except ValueError:
        error_count += 1

print(f"총 오류 횟수: {error_count}회 / 10회")
if error_count > 5:
    print("🔧 센서 점검이 필요합니다!")

    📝 전체 코드¶

    import random

def read_temperature_sensor():
    """30% 확률로 오류가 나는 온도 센서"""
    if random.random() < 0.3:
        raise ValueError("센서 응답 없음!")
    return round(random.uniform(20.0, 30.0), 1)

# 안전한 센서 모니터링
last_good_temp = 25.0
error_count = 0

print("🌡️ 스마트팜 온도 모니터링 시작!\n")

for i in range(10):
    try:
        temp = read_temperature_sensor()
        last_good_temp = temp
        print(f"[{i+1}] ✅ 온도: {temp}°C")
    except ValueError:
        error_count += 1
        print(f"[{i+1}] ⚠️ 오류! 마지막 정상값 사용: {last_good_temp}°C")

print(f"\n📊 결과: 오류 {error_count}회 / 총 10회")
if error_count > 5:
    print("🔧 센서 점검이 필요합니다!")
else:
    print("✅ 센서 상태 양호합니다.")

    ⚠️ 주의할 점¶

    1. except만 쓰면 모든 오류를 삼켜버려요!

    # ❌ 나쁜 예 - 어떤 오류인지 알 수 없음
try:
    something()
except:
    pass  # 아무것도 안 함 → 문제를 숨겨버림!

# ✅ 좋은 예 - 어떤 오류인지 명시
try:
    something()
except ValueError:
    print("값 오류가 발생했습니다")

    2. try 블록은 최소한으로!

    위험한 코드 한두 줄만 try 안에 넣으세요. 전체 프로그램을 try로 감싸면 어디서 오류가 났는지 찾기 어려워요.

    ✅ 점검하기¶

    1. 다음 코드의 출력 결과는?

    try:
    print("A")
    x = 1 / 0
    print("B")
except:
    print("C")
print("D")
    정답 확인 
    A
C
D
    "A"를 출력한 후 `1/0`에서 오류 → "B"는 건너뜀 → except의 "C" 실행 → 프로그램 계속되어 "D" 출력

    2. 센서 오류 시 마지막 정상값을 사용하는 이유는?

    정답 확인 프로그램이 멈추지 않으면서도 **합리적인 값**으로 계속 동작하기 위해서입니다. 아무 값도 없는 것보다 가장 최근의 정상 데이터를 쓰는 것이 더 안전하기 때문이에요.

    3. try 블록 안에 너무 많은 코드를 넣으면 안 되는 이유는?

    정답 확인 어디서 오류가 발생했는지 찾기 어려워지기 때문입니다. 오류가 날 수 있는 코드만 최소한으로 try 안에 넣어야 디버깅이 쉬워요.
