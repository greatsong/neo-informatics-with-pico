    디자인 씽킹과 문제해결¶

    🎯 이 장의 학습 목표¶

    • [ ] 디자인 씽킹의 5단계 프로세스를 설명할 수 있다
    • [ ] '사람 중심' 문제해결이 왜 중요한지 이해한다
    • [ ] 주변의 문제를 발견하고 프로젝트 주제 후보를 탐색할 수 있다

    예상 학습 시간: 약 40분

    📚 미리 알아야 할 것¶

    지금까지 파이썬의 다양한 기능을 배워왔어요. 이제부터는 "무엇을 만들까?"를 고민하는 시간입니다. 코딩 실력도 중요하지만, 좋은 문제를 찾는 능력이 더 중요하다는 것을 이번 장에서 함께 알아봐요!

    📚 핵심 개념¶

    개념 1: 디자인 씽킹이란?¶

    비유로 시작해 볼게요. 🩺

    병원에 갔을 때를 떠올려 보세요. 의사 선생님은 바로 약을 처방하지 않아요. 먼저 "어디가 아프세요?" 하고 물어보고, 증상을 듣고, 검사를 한 다음에야 치료 방법을 정하죠?

    디자인 씽킹도 똑같아요. "일단 뭔가 만들자!"가 아니라, "누가 어떤 문제로 힘들어하지?"를 먼저 깊이 이해한 후에 해결책을 찾는 방법이에요.

    📌 정확한 정의: 디자인 씽킹(Design Thinking)은 사람의 필요(needs)를 깊이 이해하고, 창의적인 아이디어를 빠르게 시도하며 해결책을 찾아가는 문제해결 프로세스입니다.

    디자인 씽킹은 5단계로 이루어져요.

    flowchart LR A["1️⃣ 공감\nEmpathize"] --> B["2️⃣ 문제정의\nDefine"] B --> C["3️⃣ 아이디어\nIdeate"] C --> D["4️⃣ 프로토타입\nPrototype"] D --> E["5️⃣ 테스트\nTest"] E -.->|"피드백 반영"| A style A fill:#ffebee,stroke:#c62828 style B fill:#fff3e0,stroke:#e65100 style C fill:#fffde7,stroke:#f9a825 style D fill:#e8f5e9,stroke:#2e7d32 style E fill:#e3f2fd,stroke:#1565c0

    각 단계를 쉽게 풀어볼게요.

    • 1️⃣ 공감: 문제를 겪는 사람의 입장이 되어보기 (관찰, 인터뷰)
    • 2️⃣ 문제정의: "진짜 문제"가 무엇인지 명확하게 정리하기
    • 3️⃣ 아이디어: 해결 방법을 마구 쏟아내기 (브레인스토밍)
    • 4️⃣ 프로토타입: 간단한 시제품을 빠르게 만들어보기
    • 5️⃣ 테스트: 실제 사용자에게 보여주고 피드백 받기

    💡 잠깐! 마지막 테스트에서 화살표가 다시 공감으로 돌아가는 게 보이나요? 디자인 씽킹은 한 번에 끝나는 게 아니라 피드백을 받아 계속 개선하는 과정이에요.

    개념 2: 기술 중심 vs 사람 중심¶

    여기서 가장 중요한 질문이 있어요.

    "멋진 기술을 먼저 찾을까, 아니면 사람의 문제를 먼저 찾을까?"

    flowchart TD subgraph X["❌ 기술 중심 (흔한 실수)"] A1["AI가 유행이래!"] --> A2["AI로 뭘 만들지?"] A2 --> A3["아무도 안 쓰는\n쓸데없는 앱 😢"] end subgraph O["✅ 사람 중심 (디자인 씽킹)"] B1["할머니가 약 먹는 시간을\n자꾸 잊으셔 😥"] --> B2["어떻게 도와드릴까?"] B2 --> B3["알림 프로그램 만들자!\n할머니가 편하게 쓸 수 있게 💊"] end style X fill:#ffebee,stroke:#c62828 style O fill:#e8f5e9,stroke:#2e7d32

    차이가 느껴지시나요?

    • 기술 중심: "이 기술로 뭘 만들까?" → 문제가 없는 해결책
    • 사람 중심: "이 사람의 문제를 어떻게 풀까?" → 진짜 도움이 되는 해결책

    📌 기억하세요: 세상에서 가장 뛰어난 프로그램도, 아무도 필요로 하지 않으면 의미가 없어요. 좋은 프로젝트는 항상 "누군가의 진짜 불편함"에서 시작됩니다.

    💡 여기까지 이해가 잘 되셨나요? 디자인 씽킹은 어려운 이론이 아니에요. "상대방 입장에서 생각하기"를 체계적으로 하는 것뿐이에요! 😊

    🔨 따라하기: 문제 발견 브레인스토밍¶

    이제 직접 해볼 차례예요! 파이썬으로 문제 발견 브레인스토밍 도구를 만들어 봅시다.

    Step 1: 관찰 영역 정하기¶

    먼저, 문제를 찾을 영역(장소)을 정리하는 코드를 작성해요.

    # 문제를 관찰할 영역 정하기
areas = ["학교", "집", "동네", "온라인"]

print("🔍 문제를 찾아볼 영역들:")
for i, area in enumerate(areas, 1):
    print(f"  {i}. {area}")

    실행 결과: 

    🔍 문제를 찾아볼 영역들:
  1. 학교
  2. 집
  3. 동네
  4. 온라인

    Step 2: 불편함 수집하기¶

    각 영역에서 느끼는 불편함을 입력받아 저장해요.

    # 각 영역별 불편함 수집
problems = {}

areas = ["학교", "집", "동네"]

for area in areas:
    print(f"\n📍 [{area}]에서 겪는 불편함을 입력하세요.")
    print("  (입력이 끝나면 '끝'을 입력)")

    area_problems = []
    while True:
        problem = input("  → 불편함: ")
        if problem == "끝":
            break
        area_problems.append(problem)

    problems[area] = area_problems

    Step 3: 문제 정리하고 우선순위 매기기¶

    수집한 문제들을 한눈에 보고, 영향을 받는 사람이 많은 것을 골라봐요.

    # 수집된 문제 정리
print("\n" + "=" * 40)
print("📋 발견한 문제들 정리")
print("=" * 40)

all_problems = []
for area, probs in problems.items():
    print(f"\n📍 {area}:")
    for p in probs:
        print(f"  - {p}")
        all_problems.append(f"[{area}] {p}")

# 가장 해결하고 싶은 문제 선택
print(f"\n총 {len(all_problems)}개의 문제를 발견했어요! 🎉")

    Step 4: 공감 질문 만들기¶

    선택한 문제에 대해 디자인 씽킹 1단계(공감)를 연습해요.

    # 공감 단계 연습
chosen = input("\n가장 해결하고 싶은 문제를 하나 적어주세요: ")

print(f"\n🎯 선택한 문제: '{chosen}'")
print("\n💭 공감을 위한 질문들:")

empathy_questions = [
    "이 문제를 겪는 사람은 누구인가요?",
    "그 사람은 얼마나 자주 이 문제를 겪나요?",
    "이 문제 때문에 어떤 감정을 느끼나요?",
    "지금은 이 문제를 어떻게 해결하고 있나요?",
    "이 문제가 해결되면 어떤 점이 달라질까요?"
]

for i, q in enumerate(empathy_questions, 1):
    print(f"  {i}. {q}")
    answer = input("     답변: ")

    Step 5: 문제 정의문 작성하기¶

    디자인 씽킹 2단계(문제정의)! 문제를 한 문장으로 정리해요.

    # 문제 정의문 만들기
print("\n✍️ 문제 정의문을 만들어 봅시다!")
print("형식: [누가] + [어떤 상황에서] + [어떤 문제를 겪는다]")

who = input("  누가: ")
when = input("  어떤 상황에서: ")
what = input("  어떤 문제를 겪는다: ")

statement = f"'{who}'은(는) '{when}' 상황에서 '{what}'"

print("\n" + "=" * 40)
print(f"📌 문제 정의문:")
print(f"   {statement}")
print("=" * 40)
print("\n🚀 이것이 여러분의 프로젝트 출발점이에요!")

    실행 결과 예시: 

    📌 문제 정의문:
   '우리 동네 어르신들'은(는) '병원 예약을 할 때' 상황에서 '복잡한 앱 사용이 어려워 포기한다'

    ✅ 체크포인트: 문제 정의문이 완성되었다면, 이 한 문장이 앞으로 프로젝트의 나침반 역할을 해요!

    📝 전체 코드¶

    # 🧠 디자인 씽킹 - 문제 발견 도구

# 1단계: 영역별 불편함 수집
problems = {}
areas = ["학교", "집", "동네"]

print("🔍 디자인 씽킹 - 문제 발견 브레인스토밍")
print("=" * 40)

for area in areas:
    print(f"\n📍 [{area}]에서 겪는 불편함을 입력하세요. ('끝' 입력시 다음)")
    area_problems = []
    while True:
        problem = input("  → ")
        if problem == "끝":
            break
        area_problems.append(problem)
    problems[area] = area_problems

# 정리
print("\n📋 발견한 문제들:")
for area, probs in problems.items():
    print(f"  📍 {area}: {probs}")

# 2단계: 문제 정의문 작성
print("\n✍️ 문제 정의문 작성")
who = input("  누가: ")
when = input("  어떤 상황에서: ")
what = input("  어떤 문제를: ")

print(f"\n📌 '{who}'은(는) '{when}' 상황에서 '{what}'")
print("🚀 이것이 프로젝트의 출발점입니다!")

    ⚠️ 주의할 점¶

    • "나한테는 불편하지 않은데?"는 위험한 생각이에요. 디자인 씽킹의 핵심은 다른 사람의 입장에서 생각하는 거예요. 나는 괜찮아도, 어르신·장애인·어린이 등 다른 사람에게는 큰 문제일 수 있어요.

    • 처음부터 해결책을 생각하지 마세요. "앱을 만들면 되지!"라고 바로 뛰어들면 진짜 문제를 놓칠 수 있어요. 충분히 공감하고 문제를 정의한 후에 해결책을 생각하세요.

    ✅ 점검하기¶

    1. 디자인 씽킹의 5단계를 순서대로 말해보세요.

    정답 확인 1️⃣ 공감(Empathize) → 2️⃣ 문제정의(Define) → 3️⃣ 아이디어(Ideate) → 4️⃣ 프로토타입(Prototype) → 5️⃣ 테스트(Test)

    2. "요즘 AI가 유행이니까 AI 챗봇을 만들자!"는 어떤 접근 방식이고, 왜 위험할까요?

    정답 확인 **기술 중심** 접근 방식이에요. 사람의 실제 문제를 먼저 파악하지 않고 기술부터 정했기 때문에, 아무도 필요로 하지 않는 것을 만들 위험이 있어요. 디자인 씽킹에서는 **사람 중심**으로 "누구의 어떤 문제인지"를 먼저 찾아야 해요.

    3. 좋은 문제 정의문의 세 가지 요소는 무엇인가요?

    정답 확인 **누가** + **어떤 상황에서** + **어떤 문제를 겪는지**. 예: "시각장애인은 횡단보도를 건널 때 신호등 색을 알 수 없어 위험하다."
